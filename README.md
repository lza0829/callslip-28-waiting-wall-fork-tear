# 叫号条（Callslip）

银行网点柜面叫号：取号入队 → 叫号推进 → 过号回收/重叫 → 当日队列封口。

- 前端 http://127.0.0.1:6400
- API http://127.0.0.1:11400
- `docker compose up -d --build`

## 等候墙真源口径

全局只贯彻一种架构：**以队列表为准（队列表 ∪ 位次物化 ∪ 墙可重放）**。

- `tickets` 当日 `等候`/`过号` 行是等候墙唯一真源；`wall_snapshots` 只是同事务刷新的位次物化加速缓存。
- 读墙时重算真源摘要，与快照逐字段比对：缺失标「未物化」、不一致标「陈旧」，两者都熄灭对齐灯。
- 墙面「可叫集合」也只由 `等候` 行重放，且只有在物化一致、叫号高亮与窗口当前号同源、当日未封口时才宣称可叫；任一对不上则 `可叫=false`、`可叫分栏=[]`，绝不只改墙标题或摘要亮墙齐。
- 取号/叫号/过号/重叫/办结/作废/种类启停/封口/解封/切日全部走 `BEGIN IMMEDIATE` 写事务，队列表、物化快照与墙刷新审计同提交、同回滚。
- 叫号口前置核对：物化对不上则先按队列表自愈；叫号高亮与队列表/窗口当前号对不上则返回 409 拒绝叫号。
- 纠偏入口 `POST /api/等候墙/重放`：只按队列表重放缓存并写审计，不改队列表，因此不会被误当作出队成功。
- 证据面：`GET /api/等候墙/物化`（逐种类真源/物化批次比对）、`GET /api/等候墙/审计`（每次写口的墙刷新记录）、`GET /api/总览`（含同一次读事务内的墙面核对摘要，不再叠加任何表面设置覆盖）。
- 回归测试：`cd backend && .venv/bin/python -m tests.test_wall`

测试覆盖任务夹具：墙有号队列表无、物化多号墙无、叫号高亮与可叫集合拧花、发号/过号写口分叉，以及半截写口回滚与并发写后墙队审计不分叉。
